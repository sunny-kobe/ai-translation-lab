# 模型选择与翻译流程优化

核对日期：2026-10-01。当前默认真实模型为 `glm-5.3-flash`；未选择真实 provider 时仍使用 Fake。

## 选择依据

| 模型          | 输入／百万 tokens | 输出／百万 tokens | 当前建议                                                 |
| ------------- | ----------------- | ----------------- | -------------------------------------------------------- |
| GLM-5.3       | ¥8                | ¥28               | 暂不用于日常翻译练习                                     |
| GLM-5.3-Flash | ¥0.8              | ¥2.8              | 当前默认，价格低且实测闭环可用                           |
| GLM-4.7       | ¥2                | ¥8                | 此价格只适用于输入 <32K、输出 <0.2K；长输出更贵          |
| GLM-4.7-Flash | 免费              | 免费              | 当前 key 的 4 次比较请求均返回 429；不能据此判断翻译质量 |

以上是官方标准价，未使用限时折扣或账户账单推断实际扣费。缓存命中输入的价率另计。GLM-5.3-Flash 的标准输入、输出单价均为旗舰 GLM-5.3 的十分之一。

来源：[官方 API 定价](https://docs.bigmodel.cn/cn/guide/start/pricing)、[5.3-Flash 参数](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[5.3 参数](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)。

## 同样例实测

复用 `tests/fixtures/quality.json` 的中、法、西样例，再增加日语重复占位符样例。两个候选各调用 4 次，不自动重试；调用同一个本机个人 key。

- 5.3-Flash：4/4 通过 key、语言、字符串、占位符次数和术语检查；耗时 1.022–1.656 秒，平均约 1.28 秒。
- 5.3-Flash：总输入 758 tokens、输出 101 tokens；将输入全部按未缓存标准价计算，保守估算为 ¥0.0008892。存在缓存命中，账户实际扣费未核对。
- 4.7-Flash：4/4 返回 429，尚未取得可比较的译文；只说明本轮当前 key 的请求被限流，不能推断所有账户或时段都不可用。
- 输出人工查看没有发现明显结构错误，但不是独立盲评；不能把 4/4 机械通过率写成语义准确率。

证据保存在 `output/model-comparison.json`。可用 `MODEL_COMPARE_ENABLED=1 npx tsx scripts/compare-models.ts` 重做；会实际调用模型、产生相应用量，结果覆盖本地比较文件。

## 本轮最小优化

1. 按模型配置参数。5.3 系列只支持开启思考，设置 `reasoning_effort=low`；输出上限为 8192 tokens，给思考和 JSON 留空间。4.7 系列保留关闭思考。
2. 只发送当前源文中出现的术语，减少无关输入；完整术语表仍保存在任务中，校验规则不变。
3. 识别 `finish_reason=length`，记为 `OUTPUT_TRUNCATED` 并停止原样自动重试，即使 JSON 前缀看起来合法也拒绝。排查 token 上限或拆分文案后，再主动重试。

没有改动共享契约、数据库 schema、依赖或调度结构。持久化、人工修改保护、审核后导出继续由原流程验证。

## 最没把握的事情

5.3-Flash 在长文、否定句、多义 UI 文案及跨语言术语上的语义质量。当前只有 4 个短样例；如果它翻错但结构正确，机械校验不会阻止入库。最便宜的下一次验证是收集约 20 条自有样例，先写语义要点，再隐藏模型名人工检查，记录具体失败，不急着计算泛化准确率。

## 最大的遗漏

任务和尝试历史尚未持久化模型名、prompt 版本、token 用量和费用。切模型后，单靠当前页面标签无法确定历史结果来自哪个模型；重复调用费用也无法从现有表完整还原。本轮比较产物有模型和 usage，不能替代正式调用历史。把这项作为学习后的新增 SQL 迁移练习；保留已执行的 `001_initial.sql`。

## 后续优化顺序

1. 可观察性：将模型、prompt 版本、usage 和耗时归属到具体尝试，区分估算费用与供应商账单。
2. 当前已按 key-level 批量：一个 key 一次请求全部目标语言，结果逐语言保存；下一步是用真实 50 key × 50 语言样例继续测吞吐、429 和语义质量。
3. 再考虑翻译缓存：缓存键至少包括源文、语言、术语、模型和 prompt 版本；人工改动必须优先。先测重复率，再决定是否值得实现。
