# 按 key 多语言翻译升级（2026-10-02 已授权实施）

用户明确修正：一次请求只包含一个 key，覆盖该 key 全部所选语言（最多 50）；不得按语言拆成 N × L 次请求。数据库仍按 key × language 保存结果。默认模型 GLM-5.3-Flash，默认并发 2，可配置 1–4。

## 范围与顺序

1. 扩展 50 种语言目录、运行时契约和 searchable multi-select，提供全选/清空；单 key 多语言 provider 返回严格语言数组。
2. 追加 002 迁移：任务模型/prompt 快照、模型请求记录、逐项请求关联、持久化 next_attempt_at 与全局冷却。旧数据模型不伪造回填。
3. worker 按 job/key 领取全部可执行语言，一次调用；同 key 不重叠。短事务先锁 job 再锁 result，等待模型期间不持有事务。结果逐项校验/条件写回，缺语言只重试缺失项，重复/额外语言不接受模糊结果。
4. 默认并发 2。调度释放失败槽，重试时间入库；429 按 Retry-After 或指数退避统一冷却。启动/异常恢复排除当前在途调用；锁丢失停止新领取。
5. 完成 50×50 的真实 PG/Fake 验收、并发上限、部分成功、人工修改、错误结构、定时重试、模型快照、SIGKILL 恢复，以及真实一个 key×50 语言和多 key 浏览器 smoke。语义质量与机械检查分开报告。

## 请求数与长文

N 个 key × L 语言成功路径为 N 次请求，数据库有 N×L 个结果。失败重试、崩溃可能增加请求，不保证计费 exactly-once。长文仍保持单 key 请求，动态提高输出 token 上限到模型允许范围；供应商明确截断时失败并报告，不能自动切回按语言发请求。

## 历史、回滚与限制

新增任务固定 provider/model/prompt；旧已完成数据 metadata=null 表示 unknown。旧未完成任务首次执行明确采纳当前配置，不声称原模型可追溯。usage 以模型请求为单位只存一次，结果尝试关联请求；无法获取的用量为 null。费用估算标明价率日期，不替代账单。

只改本项目应用、共享契约、追加 SQL、测试与文档。无公司数据库、无删数据、无新依赖、无 Git 提交/远程操作。并发可降到 1；数据库采用增量迁移，回滚不得删除历史。账户真实并发限额与全语言语义评审仍需独立证据。

## 实施结果

已按本方案实施。当前 `translation_calls` 是一次 key-level provider 请求的持久化记录；一个 key 的多个语言结果通过 `call_id` 关联。默认并发 2，`TRANSLATOR_CONCURRENCY` 可设置 1–4。真实 1 key × 50 languages 已验证 1 次智谱请求产出 50/50 结果；Fake 50 keys × 50 languages 验证 50 次调用、2500 条结果，4 key 并发峰值为 2。
